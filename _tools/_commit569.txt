569: T1 restored to 1.0% as a geometric cascade (1.0/0.5/0.25/0.125, sum 1.875%); the entire prop-firm drawdown layer deleted, sizing pure equity-based

RATIONALE

  Two requests, one release: put the initial risk back where it was before
  v5.68 halved it, and strip every trace of the prop-firm drawdown /
  evaluation machinery. Both are shape changes to the risk model rather than
  tuning, so they land together and the ladder is documented as one coherent
  design instead of two half-states.

RISK -- T1 restored, the three scale-ins NOT

  v5.68 halved all four rungs, which turned the v5.61+ FLAT HEAD into
  0.5 / 0.5 / 0.25 / 0.125. v5.69 restores ONLY T1 and leaves T2/T3/T4 exactly
  where v5.68 put them:

      rung                     trigger           v5.68     v5.69
      T1  RiskPercent          at market          0.5%  ->  1.0%
      T2  InpRiskT2Pct         +1.0R              0.5%      0.5%   unchanged
      T3  InpRiskT3Pct         +2.0R              0.25%     0.25%  unchanged
      T4  InpRiskT4Pct         +3.0R              0.125%    0.125% unchanged
                                                --------     --------
      summed stacked exposure                  1.375%   ->  1.875%

  This is NOT a revert of v5.68 and it is NOT a restore of v5.67. It is
  v5.68's ladder with the head doubled, which makes the ladder a strict
  GEOMETRIC CASCADE: every rung risks exactly half the rung above it. The
  flat head (T1 == T2) that v5.61 established is deliberately GONE, and the
  4th rung stays at 0.125% rather than being rescaled.

  Only LOTS and MONEY change. Every scale-in trigger, breakeven floor, profit
  lock and ATR-trail rung is an R-multiple of the primary's own 1R, so no
  price level moves and no milestone re-times. No formula changed:
  GetRiskMoney(), CalculateLotSize() and RiskPctLotSize() all read
  RiskPercent dynamically at call time.

  The per-leg abort ceiling moves with T1 for free, because it was never an
  input: CHighTableAuditor::AuditRiskExposure() derives
  maxAllowedRiskPct = RiskPercent * 1.50, so it reads 1.5% on this ladder.
  That is numerically the same as the dead SafetyMaxRiskPct default, which is
  a coincidence of the two constants, not a wiring -- nothing ever connected

PROP-FIRM DRAWDOWN LAYER -- DELETED IN FULL

  Sizing is now PURE EQUITY-BASED: RiskPercent% of live equity at order time,
  with no drawdown circuit breaker of any kind. Removed outright, with no
  no-op stubs left behind:

    * the 3% daily drawdown pause (cancelled pendings, blocked placement for
      the rest of the session)
    * the 5% trailing total drawdown halt (closed the whole basket, cancelled
      every pending order, permanently halted the EA)
    * the 00:00 MT5 server-time reset clock: MostRecentServerMidnight() and
      CheckDailyReset()
    * the MT5 GlobalVariable persistence layer: OttoGvName/LoadDouble/
      LoadFlag/Store/StoreFlag and PersistSafetyState(). The EA now writes no
      drawdown state to the terminal's shared GV store, so a VPS restart can
      no longer resurrect a stale pause, halt or high-water mark.
    * the equity high-water mark and the daily reset anchor globals
    * OnTick's entire STEP 0 block (equity HWM ratchet, both breach branches,
      the breach-path CancelAllPendingOrders/CloseEntireBasket, and the
      g_totalDD_Halted early return at the top of the handler)
    * the !g_dailyDD_Paused wrapper around PlaceOrdersForArmedBlocks(), so
      placement is now unconditional at STEP 4
    * the DailyDD/TotalDD columns in LogStatus() and in the init banner
    * CHighTableAuditor's mirror: AuditDrawdown(), DailyDDPct(), TotalDDPct(),
      SetSafetyBaseline(), the four pushed members and the three DD latches.
      AuditRiskExposure() SURVIVES -- the per-leg runaway-size check is not
      part of the drawdown layer and is now the only risk watchdog left.

  The three prop-firm inputs are DELETED, not retired to no-ops:

      SafetyMaxRiskPct    1.5   -- never read by anything in the tree
      SafetyDailyDDLimit  3.0   -- only the deleted daily pause read it
      SafetyTotalDDLimit  5.0   -- only the deleted trailing halt read it

  This breaks with the v5.63 pattern on purpose. The retired veto inputs
  ([7] news, [9] vector) were LIVE READS that got switched off, so an old
  .set file legitimately still carries them and keeping the declarations
  costs nothing. These three never affected behaviour at any point, and a
  knob that silently changes nothing is worse than no knob -- it advertises a
  limit the EA does not enforce. MT5 tolerates a .set naming an absent input.

  Group [8] PROP FIRM SAFETY BUFFERS is gone from the input roster. Groups
  [9]-[12] keep their numbers; the gap in the numbering is intentional and
  documented in place, because renumbering would invalidate every screenshot,
  .set comment and journal reference to "[10] HIGH TABLE AUDITOR".

BEHAVIOURAL DELTA AN OPERATOR SHOULD KNOW

  * A 5% drawdown no longer stops the EA. It will keep taking new setups
    through an unrecovered drawdown, because the breaker that used to halt it
    is gone. This is the deliberate consequence of the request, not an
    oversight -- but it belongs in the release note rather than in the diff.
  * The initial position is twice the size it was in v5.68 (1.0% vs 0.5%),
    and the fully-stacked basket risks 1.875% of equity instead of 1.375%.
  * Nothing is remembered across a restart any more. A VPS bounce resets
    every piece of EA state, which is now only in-memory trade/block state
    that was already re-synced from the book in OnInit().
  * An old .set file naming SafetyMaxRiskPct / SafetyDailyDDLimit /
    SafetyTotalDDLimit still loads; MT5 simply reports the unknown input and
    ignores it. No migration step is required.

NOT DONE ON PURPOSE

  * No push. v5.68 and v5.69 both await operator approval; `origin` stays at
    v5.67 (f5410d2).
  * The four R-multiple triggers were not retuned. The cascade is a change to
    how much is risked at each milestone, not to when each milestone fires.
  * The three drifted probes (v531, v532, v543) were not repaired; they were
    only kept from regressing further.
