  -- CLAUSE 2 (crossing guard) VERIFIED ALREADY DONE, v5.64 -----------------

  IsEntryCrossed(), COttoOrderManager.mqh:237:

      return isLong ? (GetAsk() >= entryPrice) : (GetBid() <= entryPrice);

  This is the EXACT NEGATION of the virtual trigger test at line 2769
  (`isLong ? (ask < triggerPrice) : (bid > triggerPrice)`), evaluated on the
  same price side, so the arm-time answer and the fire-time answer cannot
  disagree by a spread.

  Wiring is at line 924, and the ORDER of the two clauses is load-bearing:

      if(InpEntryStyle != ENTRY_MIDPOINT && IsEntryCrossed(block, entryPrice))

  It runs AHEAD of GetPriceBoundaryBuffer(), i.e. before the hybrid router
  chooses physical vs virtual. For ENTRY_FRONT_EDGE, "priceValid" (legal to
  REST) already implies "crossed", so a guard placed inside the virtual
  branch only would have let the router REST a chasing limit below market --
  precisely the case the guard exists to refuse. Ahead of the router, a
  crossed setup can become neither a chase limit nor an instant virtual fire.

  On a hit the block is LATCHED (hasPlacedOrder = true, persisted through
  SetBlockAt): the setup is SPENT, not deferred, so PlaceOrdersForArmedBlocks
  does not re-test it every tick. It logs its own reason, ENTRY ALREADY
  CROSSED, and deliberately does NOT set isVetoed -- the ZONE is still
  structurally valid, only this setup is stale.

  TWO DEVIATIONS FROM THE LITERAL REQUEST, intentional and stated here
  rather than left to be discovered:

    1. The guard is scoped InpEntryStyle != ENTRY_MIDPOINT. A midpoint entry
       sits INSIDE the zone and is therefore behind the market by
       construction, so an unscoped test is TRUE on every healthy midpoint
       setup and would retire that style outright (zero trades).
    2. The reversal and pyramid paths stay guard-EXEMPT. OpenReversalPosition()
       and AddPyramidTranche() both enter at the live GetAsk()/GetBid() and
       never price off CalcEntryPrice(), so the guard would be true on every
       call and would retire SAR flips and scale-ins. Both exemptions are
       documented at their call sites in the source; neither was applied
       silently.
